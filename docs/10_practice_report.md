# ОТЧЁТ ПО УЧЕБНОЙ ПРАКТИКЕ

## Введение
Цель практики — получить навыки проектирования, разработки, интеграции и тестирования программных модулей на примере учебной операционной системы StudentOS.

## 1. Постановка задачи
Требовалось разработать учебную ОС с ядром, базой данных, пользователями, файловой системой, процессами, памятью, системными вызовами, оболочкой, тестами и документацией.

## 2. Использованные технологии
Python 3.10+, SQLite, VS Code, Git, Markdown, Draw.io/PNG-диаграммы.

## 3. Архитектура системы
Система состоит из модулей `db`, `kernel`, `auth`, `logger`, `fs`, `scheduler`, `syscalls`, `shell`. Оболочка вызывает системные вызовы, системные вызовы обращаются к подсистемам, подсистемы используют слой БД.

## 4. Реализация базы данных
`db.py` создаёт таблицы `roles`, `users`, `files`, `processes`, `memory_state`, `syscalls_log`. Для доступа реализованы CRUD-функции.

## 5. Реализация ядра
`kernel.py` хранит текущего пользователя, счётчик PID, состояние памяти, лимит памяти, умеет выделять и освобождать память.

## 6. Аутентификация и безопасность
`auth.py` хэширует пароли SHA-256, регистрирует пользователей и проверяет роли. `check_permission` запрещает обычному пользователю удалять чужие файлы и завершать чужие процессы.

## 7. Файловая система
Файлы и каталоги хранятся в SQLite. Реализованы создание, чтение, запись, удаление, список, дерево, копирование, перемещение и переименование.

## 8. Планировщик процессов
`scheduler.py` создаёт процессы, показывает список, завершает процессы, использует Round Robin и взаимодействует с памятью ядра.

## 9. Системные вызовы и shell
`syscalls.py` предоставляет API для shell: login, files, dirs, processes, memory, logs. `shell.py` реализует команды пользователя.

## 10. Интеграция
Подсистемы соединены через системные вызовы. Реальные проблемы интеграции: чтение файла было заглушкой, проверка владельца отсутствовала, память не освобождалась после kill. Все проблемы исправлены.

## 11. Тестирование
Проведены модульные, функциональные, интеграционные, системные, регрессионные и стресс-тесты.

Основные дефекты: заглушка чтения файла, отсутствие проверки владельца, отсутствие освобождения памяти. Статус всех дефектов — закрыт.

## 14. Выполнение требований
NFR по производительности, безопасности, надёжности, сопровождаемости и переносимости выполнены на уровне учебного проекта.

## 15. Результаты практики
Получилась рабочая учебная ОС, запускаемая командой `python -m src.shell`, с документацией и тестами.

## 16. Заключение
За время практики были изучены модульная архитектура, SQLite, системные вызовы, тестирование, Git и оформление технической документации.
