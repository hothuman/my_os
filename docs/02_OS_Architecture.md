# Архитектура StudentOS

## 1. Архитектура ОС и список модулей

StudentOS — учебная модель операционной системы, реализованная на Python с использованием SQLite.

Архитектура системы построена так, чтобы пользовательская оболочка не работала с базой данных напрямую. Пользователь вводит команды в оболочке, оболочка вызывает системные вызовы, системные вызовы передают запрос ядру, а ядро взаимодействует с отдельными подсистемами операционной системы.

Общее направление вызовов:

```text
shell.py
    ↓
syscalls.py
    ↓
kernel.py
    ↓
scheduler.py / memory.py / fs.py / auth.py
    ↓
db.py
```

Таким образом, `shell.py` работает только через системные вызовы, а непосредственное взаимодействие с хранилищем данных выполняют внутренние модули системы.

### shell.py

Командная оболочка StudentOS.

Получает команды пользователя, выводит результаты работы системы и вызывает функции из `syscalls.py`.

Оболочка не должна обращаться к SQLite напрямую.

### syscalls.py

Модуль системных вызовов.

Предоставляет оболочке единый интерфейс для работы с возможностями операционной системы: авторизацией, файлами, процессами, памятью, журналом и завершением работы.

Также модуль записывает информацию о выполненных системных вызовах в таблицу `syscalls_log`.

### kernel.py

Центральный модуль StudentOS.

Ядро принимает запросы от системных вызовов и передаёт выполнение соответствующим подсистемам.

Через ядро выполняется взаимодействие с:

- планировщиком процессов;
- памятью;
- файловой системой;
- системой авторизации.

### scheduler.py

Подсистема управления процессами.

Отвечает за учебную модель процессов:

- запуск процесса;
- получение списка процессов;
- завершение процесса;
- хранение состояния процесса.

Информация о процессах хранится в SQLite.

### memory.py

Подсистема управления памятью.

Моделирует выделение памяти процессам и контролирует использование установленного в StudentOS условного лимита памяти.

Информация об объёме памяти процесса может храниться в таблице `processes`.

### fs.py

Подсистема файловой системы.

Отвечает за операции с учебными файлами:

- создание файла;
- чтение файла;
- удаление файла;
- получение списка файлов.

Файлы моделируются записями в таблице `files` базы SQLite.

### auth.py

Подсистема аутентификации пользователей.

Проверяет существование пользователя, логин и пароль.

Пароли не должны храниться в открытом виде. Для проверки используются хэши паролей из таблицы `users`.

### db.py

Модуль работы с базой данных SQLite.

Отвечает за:

- создание подключения к базе;
- инициализацию таблиц;
- предоставление соединения внутренним модулям системы.

Основной файл базы данных:

```text
db/os.sqlite
```

## 2. Системные вызовы

Системные вызовы являются интерфейсом между командной оболочкой и внутренними механизмами StudentOS.

### 2.1 Вход пользователя

```python
sys_login(login: str, password: str) -> bool
```

Проверяет логин и пароль пользователя.

Возвращает:

- `True` — если вход выполнен успешно;
- `False` — если данные неверны.

### 2.2 Выход пользователя

```python
sys_logout() -> bool
```

Завершает текущий пользовательский сеанс.

Возвращает `True` при успешном выходе.

### 2.3 Получение текущего пользователя

```python
sys_whoami() -> str
```

Возвращает имя текущего пользователя.

Например:

```text
guest
```

или:

```text
admin
```

### 2.4 Создание файла

```python
sys_create_file(path: str, content: str) -> int
```

Создаёт новый учебный файл.

Параметры:

- `path` — путь файла;
- `content` — содержимое файла.

Возвращает числовой идентификатор созданного файла.

### 2.5 Чтение файла

```python
sys_read_file(path: str) -> str
```

Получает содержимое файла по указанному пути.

Возвращает строку с содержимым файла.

### 2.6 Удаление файла

```python
sys_delete_file(path: str) -> bool
```

Удаляет учебный файл.

Возвращает `True`, если операция выполнена успешно.

### 2.7 Получение списка файлов

```python
sys_list_files(path: str) -> list
```

Возвращает список файлов для указанного пути.

Результат имеет тип `list`.

### 2.8 Запуск процесса

```python
sys_exec(name: str) -> int
```

Моделирует запуск нового процесса.

Возвращает PID созданного процесса.

В учебной заглушке может возвращаться значение:

```text
42
```

### 2.9 Получение списка процессов

```python
sys_ps() -> list
```

Возвращает список процессов StudentOS.

Для начальной заглушки допустим результат:

```python
[]
```

### 2.10 Завершение процесса

```python
sys_kill(pid: int) -> bool
```

Завершает процесс с указанным PID.

Возвращает `True`, если операция выполнена успешно.

### 2.11 Выделение памяти

```python
sys_mem_alloc(size: int) -> int
```

Моделирует выделение памяти.

Параметр `size` задаёт требуемый объём памяти.

Возвращает числовое значение, связанное с результатом выделения памяти.

### 2.12 Просмотр журнала

```python
sys_logs(limit: int) -> list
```

Возвращает последние записи журнала системных вызовов.

Параметр `limit` определяет максимальное количество возвращаемых записей.

### 2.13 Завершение работы системы

```python
sys_shutdown() -> bool
```

Моделирует завершение работы StudentOS.

Возвращает `True` при успешном выполнении.

## 3. Контракты системных вызовов

### 3.1 Контракт sys_login

```python
sys_login(login: str, password: str) -> bool
```

**Предварительное условие:**  
В базе данных существует пользователь с указанным логином.

**Постусловие:**  
Функция возвращает `True` при правильном пароле или `False`, если данные авторизации неверны.

**Побочный эффект:**  
Информация о системном вызове записывается в таблицу `syscalls_log`.

---

### 3.2 Контракт sys_create_file

```python
sys_create_file(path: str, content: str) -> int
```

**Предварительное условие:**  
Пользователь авторизован, а путь файла передан в допустимом формате.

**Постусловие:**  
После успешного выполнения создаётся новый файл и возвращается его числовой идентификатор.

**Побочный эффект:**  
В таблице `files` появляется новая запись, а вызов записывается в `syscalls_log`.

---

### 3.3 Контракт sys_kill

```python
sys_kill(pid: int) -> bool
```

**Предварительное условие:**  
Процесс с указанным PID существует в системе.

**Постусловие:**  
После успешного выполнения процесс считается завершённым, а функция возвращает `True`.

**Побочный эффект:**  
Изменяется состояние процесса и создаётся новая запись в таблице `syscalls_log`.

## 4. Структуры данных

Для представления основных объектов StudentOS используются структуры, похожие на Python-словари.

### 4.1 Структура process

Структура описывает процесс учебной операционной системы.

```python
process = {
    "pid": 1,
    "name": "demo",
    "state": "running",
    "owner": "admin",
    "memory": 16,
    "created_at": "2026-09-29 15:00:00"
}
```

Поля:

- `pid` — идентификатор процесса;
- `name` — имя процесса;
- `state` — состояние процесса;
- `owner` — владелец процесса;
- `memory` — выделенный объём памяти;
- `created_at` — время создания процесса.

### 4.2 Структура file

Структура описывает файл в учебной файловой системе.

```python
file = {
    "id": 1,
    "path": "/test.txt",
    "content": "hello",
    "owner": "admin",
    "created_at": "2026-09-29 15:00:00"
}
```

Поля:

- `id` — идентификатор файла;
- `path` — путь к файлу;
- `content` — содержимое файла;
- `owner` — владелец;
- `created_at` — время создания.

### 4.3 Структура user

Структура описывает пользователя StudentOS.

```python
user = {
    "id": 1,
    "login": "admin",
    "password_hash": "sha256_hash",
    "role": "admin"
}
```

Поля:

- `id` — идентификатор пользователя;
- `login` — имя пользователя;
- `password_hash` — хэш пароля;
- `role` — роль пользователя.

Пароль в открытом виде в структуре не хранится.

### 4.4 Структура log

Структура описывает запись журнала системных вызовов.

```python
log = {
    "id": 1,
    "syscall_name": "sys_login",
    "args": "admin",
    "user": "admin",
    "status": "OK",
    "timestamp": "2026-09-29 15:00:00"
}
```

Поля:

- `id` — идентификатор записи журнала;
- `syscall_name` — имя системного вызова;
- `args` — переданные аргументы;
- `user` — пользователь, выполнивший вызов;
- `status` — результат выполнения;
- `timestamp` — время выполнения вызова.

## Итоговая схема взаимодействия компонентов

StudentOS использует следующую архитектуру:

```text
                         shell.py
                            ↓
                        syscalls.py
                            ↓
                         kernel.py
                            ↓
          ┌─────────────┬─────────────┬─────────────┬─────────────┐
          ↓             ↓             ↓             ↓
    scheduler.py     memory.py       fs.py         auth.py
          ↓             ↓             ↓             ↓
                         db.py
```

Основное правило архитектуры: пользовательская оболочка не работает с SQLite напрямую. Все действия выполняются через системные вызовы и внутренние модули StudentOS.
