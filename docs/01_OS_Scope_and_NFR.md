# StudentOS: границы системы и нефункциональные требования

## Концепция
StudentOS — учебная ОС-симулятор на Python и SQLite. Цель — показать работу ядра, системных вызовов, файловой системы, процессов, памяти, пользователей и журналирования.

## Границы системы
Входит: shell, syscalls, kernel, auth, fs, scheduler, memory, logger, db. Не входит: загрузчик, драйверы устройств, сеть, реальная многозадачность, GUI.

## Нефункциональные требования
- P-1: среднее время простого syscall ≤ 50 мс.
- P-2: не менее 10 процессов.
- P-3: запуск shell ≤ 2 сек.
- P-4: вывод 100 логов ≤ 1 сек.
- P-5: повторный init_db ≤ 1 сек.
- R-1: ошибка команды не роняет shell.
- R-2: ошибка процесса не роняет систему.
- R-3: повторный init_db сохраняет данные.
- R-4: отсутствующий файл обрабатывается безопасно.
- R-5: превышение памяти не повреждает БД.
- S-1: пароли SHA-256.
- S-2: user не удаляет чужие файлы.
- S-3: syscalls логируются.
- S-4: logs доступны admin.
- S-5: пароль не пишется в журнал.
- M-1: минимум 5 модулей.
- M-2: модули учебного размера.
- M-3: понятные имена функций.
- M-4: общий logger.
- M-5: pathlib для путей.
- U-1: Python 3.10+.
- U-2: без внешней СУБД.
- U-3: один SQLite-файл.
- U-4: без обязательных внешних пакетов.
- U-5: лимит памяти задаётся в config.

## Риски
Основные риски: ошибки прав доступа, потеря данных, рост модулей, циклические импорты. Снижение: тесты, logger, CRUD-слой, run_all.

## Словарь
