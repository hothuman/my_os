# Спецификации модулей StudentOS

## 1. Модуль `db.py`

### Назначение

Модуль `db.py` обеспечивает работу StudentOS с локальной базой данных SQLite. Он создаёт подключение к базе, инициализирует необходимые таблицы при первом запуске и предоставляет другим модулям общий способ выполнения SQL-запросов.

### Публичный интерфейс

#### `get_connection() -> sqlite3.Connection`

Создаёт и возвращает соединение с базой данных `db/os.sqlite`.

Соединение использует `sqlite3.Row`, поэтому значения строк можно получать по именам столбцов.

#### `init_db() -> None`

Инициализирует базу данных.

Если таблиц ещё нет, создаются:

- `users`;
- `processes`;
- `files`;
- `syscalls_log`.

Также при необходимости создаются начальные пользователи `admin` и `student`.

Повторный вызов `init_db()` не удаляет существующие данные.

#### `execute_query(sql: str, params: tuple = ())`

Выполняет SQL-запрос с переданными параметрами.

Для `SELECT` возвращает список словарей.

Пример:

```python
[
    {"username": "admin", "role": "admin"},
    {"username": "student", "role": "user"}
]
```

Для запросов изменения данных выполняется `commit()`, после чего возвращается `lastrowid`.

При `sqlite3.IntegrityError` функция возвращает `None`.

При `sqlite3.OperationalError` выводится понятное сообщение об ошибке и возвращается `None`.

### Внутренние зависимости

Модуль использует:

- `sqlite3`;
- `hashlib`;
- `datetime`;
- `config.py`.

Из `config.py` используются:

- `DB_DIR`;
- `DB_PATH`;
- данные начального администратора;
- данные начального пользователя.

### Обработка ошибок

`execute_query()` обрабатывает:

- `sqlite3.IntegrityError`;
- `sqlite3.OperationalError`.

Соединение SQLite создаётся с:

```python
timeout=5
```

При ошибке целостности или операционной ошибке программа не должна аварийно завершаться внутри `execute_query()`.

### Побочные эффекты

Модуль может:

- создать каталог `db`;
- создать `db/os.sqlite`;
- создать таблицы базы данных;
- добавить начальные учётные записи;
- читать и изменять данные SQLite;
- выполнять `commit()`.

## 2. Модуль `syscalls.py`

### Назначение

Модуль `syscalls.py` предоставляет командной оболочке StudentOS единый интерфейс системных вызовов.

Он связывает команды пользователя с внутренними модулями системы и записывает сведения о выполняемых операциях в `syscalls_log`.

### Публичный интерфейс

#### `log_syscall(name, args="", user="system", status="OK") -> None`

Записывает системный вызов в таблицу `syscalls_log`.

Сохраняются:

- имя вызова;
- аргументы;
- пользователь;
- статус;
- время.

#### `sys_login(login: str, password: str, current_user="guest") -> bool`

Проверяет логин и пароль через `authenticate()`.

При успешной проверке возвращает:

```python
True
```

При неправильном логине или пароле:

```python
False
```

В журнал записывается `OK` или `DENIED`.

#### `sys_logout(current_user="guest") -> bool`

Моделирует выход пользователя из системы.

Возвращает `True`.

#### `sys_whoami(current_user="guest") -> str`

Возвращает имя текущего пользователя.

#### `sys_create_file(path: str, content: str, current_user="guest") -> int`

Создаёт учебный файл через `fs.create_file()`.

Возвращает идентификатор созданной записи.

#### `sys_read_file(path: str, current_user="guest") -> str`

На текущем этапе остаётся учебной реализацией чтения.

Возвращает:

```python
""
```

и записывает вызов в журнал.

#### `sys_delete_file(path: str, current_user="guest") -> bool`

Удаляет файл с проверкой прав доступа.

Сначала определяется владелец файла.

После этого вызывается:

```python
check_permission(
    current_user,
    "delete_file",
    target_owner=owner,
)
```

До проверки в журнал записывается:

```text
check
```

Если пользователь не имеет прав, записывается:

```text
DENIED
```

и возвращается:

```python
False
```

Если файл успешно удалён, записывается:

```text
OK
```

и возвращается:

```python
True
```

Если файл не существует, записывается:

```text
NOT_FOUND
```

и возвращается `False`.

#### `sys_list_files(path="/", current_user="guest") -> list`

Получает список файлов через `fs.list_files()`.

#### `sys_exec(name: str, current_user="guest") -> int`

Учебная реализация запуска процесса.

На текущем этапе возвращает условный PID:

```python
42
```

#### `sys_ps(current_user="guest") -> list`

Учебная реализация получения списка процессов.

На текущем этапе возвращает:

```python
[]
```

#### `sys_kill(pid: int, current_user="guest") -> bool`

Завершает процесс с проверкой прав доступа.

Сначала записывается статус:

```text
check
```

Затем вызывается:

```python
check_permission(current_user, "kill_process")
```

Завершать процессы разрешено только администратору.

При отказе записывается:

```text
DENIED
```

и возвращается `False`.

При успешном завершении:

```text
OK
```

и возвращается `True`.

Если процесс не найден:

```text
NOT_FOUND
```

и возвращается `False`.

#### `sys_mem_alloc(size: int, current_user="guest") -> int`

Учебная реализация выделения памяти.

Возвращает переданный размер.

#### `sys_logs(limit: int = 20, current_user="guest") -> list`

Возвращает последние записи таблицы `syscalls_log`.

#### `sys_shutdown(current_user="guest") -> bool`

Моделирует завершение StudentOS.

Возвращает `True`.

#### `sys_echo(message, current_user="guest")`

Возвращает переданное сообщение и записывает вызов в журнал.

#### `sys_get_users(current_user="guest") -> list`

Возвращает список пользователей из таблицы `users`.

### Внутренние зависимости

Модуль использует:

- `db.py` — `get_connection()` и `init_db()`;
- `auth.py` — `authenticate()` и `check_permission()`;
- `fs.py` — `create_file()`, `delete_file()` и `list_files()`;
- `scheduler.py` — `kill_process()`;
- `datetime` — время записи системного вызова.

### Обработка ошибок

`sys_login()` возвращает `False` при неправильных данных и записывает статус `DENIED`.

`sys_create_file()` при ошибке записывает статус вида:

```text
ERROR: описание ошибки
```

после чего повторно передаёт исключение вызывающему коду.

`sys_delete_file()` безопасно обрабатывает отсутствие файла и отсутствие прав.

Если файл отсутствует:

```text
NOT_FOUND
```

Если доступ запрещён:

```text
DENIED
```

В обоих случаях возвращается `False`.

`sys_kill()` при недостаточных правах возвращает `False` и записывает `DENIED`.

Если PID отсутствует, записывается `NOT_FOUND`.

### Побочные эффекты

Системные вызовы создают записи в:

```text
syscalls_log
```

`sys_create_file()` создаёт записи в `files`.

`sys_delete_file()` может удалять записи из `files`.

`sys_kill()` может менять состояние процесса на `terminated`.

`sys_get_users()` читает таблицу `users`.

## 3. Модуль `kernel.py`

### Назначение

Модуль `kernel.py` содержит класс `Kernel`, моделирующий центральную часть StudentOS.

Он хранит состояние пользователя, проверяет авторизацию, роль, лимит процессов и лимит памяти.

### Публичный интерфейс

#### `Kernel()`

Создаёт объект ядра.

Начальный пользователь:

```text
guest
```

Начальная роль:

```text
guest
```

#### `username`

Возвращает имя текущего пользователя.

#### `role`

Возвращает роль пользователя.

#### `login(username, password)`

Проверяет имя пользователя и SHA-256 хэш пароля.

При успешном входе изменяет `current_user`.

#### `logout()`

Сбрасывает пользователя до `guest`.

#### `require_login()`

Проверяет наличие авторизованного пользователя.

#### `require_admin()`

Проверяет наличие роли `admin`.

#### `can_manage_owner(owner) -> bool`

Возвращает `True`, если пользователь является администратором или владельцем объекта.

#### `process_count() -> int`

Возвращает количество работающих процессов.

#### `memory_used() -> int`

Возвращает используемый объём условной памяти.

#### `check_process_limit()`

Проверяет максимальное количество процессов.

#### `check_memory(additional_mb)`

Проверяет возможность выделения дополнительной памяти.

### Внутренние зависимости

Используются:

- `config.py`;
- `db.py`;
- `hashlib`.

### Обработка ошибок

Возможны:

- `ValueError`;
- `PermissionError`;
- `RuntimeError`;
- `MemoryError`.

### Побочные эффекты

`login()` и `logout()` изменяют `current_user`.

Другие методы могут читать таблицы `users` и `processes`.

## 4. Модуль `scheduler.py`

### Назначение

Модуль реализует учебное управление процессами.

### Публичный интерфейс

#### `create_process(name: str, owner: str, memory: int = 0) -> int`

Создаёт процесс со статусом:

```text
running
```

и возвращает PID.

#### `get_processes() -> list`

Возвращает список процессов.

#### `kill_process(pid: int) -> bool`

Изменяет состояние процесса на:

```text
terminated
```

Возвращает `True`, если процесс найден.

### Внутренние зависимости

Используются:

- `db.py`;
- `datetime`.

Модуль работает с таблицей `processes`.

### Обработка ошибок

Неизвестный PID не вызывает исключение.

`kill_process()` возвращает `False`.

Ошибки SQLite передаются вызывающему коду.

### Побочные эффекты

`create_process()` добавляет процесс.

`kill_process()` изменяет его состояние.

---

## 5. Модуль `memory.py`

### Назначение

Модуль моделирует управление условной оперативной памятью StudentOS.

### Публичный интерфейс

#### `get_used_memory() -> int`

Возвращает общий объём памяти работающих процессов.

#### `get_free_memory() -> int`

Возвращает оставшийся объём памяти.

#### `allocate_memory(pid: int, size: int) -> int`

Выделяет процессу дополнительную память.

### Внутренние зависимости

Используются:

- `config.py`;
- `db.py`.

### Обработка ошибок

Возможны:

- `ValueError` — неправильный размер;
- `MemoryError` — превышен лимит;
- `ProcessLookupError` — процесс не найден.

### Побочные эффекты

`allocate_memory()` изменяет значение `memory` процесса.

## 6. Модуль `fs.py`

### Назначение

Модуль реализует учебную файловую систему StudentOS.

Файлы хранятся в SQLite.

### Публичный интерфейс

#### `create_file(path: str, content: str, owner: str) -> int`

Создаёт файл.

#### `read_file(path: str) -> str`

Возвращает содержимое файла.

При отсутствии файла возвращает:

```python
""
```

#### `delete_file(path: str) -> bool`

Удаляет файл.

Возвращает `True`, если файл был найден.

#### `list_files(path: str = "/") -> list`

Возвращает список файлов.

На текущем этапе параметр `path` не используется для фильтрации.

### Внутренние зависимости

Используются:

- `db.py`;
- `datetime`.

### Обработка ошибок

Отсутствующий файл при чтении приводит к возврату пустой строки.

Удаление отсутствующего файла возвращает `False`.

При создании дубликата пути SQLite может вызвать `IntegrityError`.

### Побочные эффекты

Модуль создаёт и удаляет записи таблицы `files`.

## 7. Модуль `auth.py`

### Назначение

Модуль отвечает за аутентификацию пользователей и проверку прав доступа.

### Публичный интерфейс

#### `hash_password(password: str) -> str`

Вычисляет SHA-256 хэш пароля.

#### `authenticate(login: str, password: str)`

Проверяет логин и пароль.

При успехе возвращает:

```python
{
    "id": 1,
    "username": "admin",
    "role": "admin"
}
```

При ошибке возвращает:

```python
None
```

#### `check_permission(current_user: str, action: str, target_owner=None) -> bool`

Проверяет право пользователя выполнить действие.

Правила:

- `admin` имеет полный доступ;
- обычный пользователь может удалить только собственный файл;
- `guest` не может удалять файлы;
- завершать процессы может только `admin`;
- неизвестное действие запрещается.

Если действие разрешено:

```python
True
```

Если запрещено:

```python
False
```

### Внутренние зависимости

Используются:

- `db.py`;
- `hashlib`.

Модуль читает таблицу `users`.

### Обработка ошибок

Отсутствующий пользователь при аутентификации приводит к возврату `None`.

Неправильный пароль приводит к возврату `None`.

`check_permission()` рассматривает неизвестного пользователя как `guest`.

Неизвестное действие запрещается и возвращает `False`.

### Побочные эффекты

Модуль не изменяет пароли или пользователей.

Он только читает данные из `users`.

## 8. Модуль `shell.py`

### Назначение

Модуль реализует текстовую командную оболочку StudentOS.

### Публичный интерфейс

#### `print_banner() -> None`

Выводит информацию о StudentOS.

#### `print_files(files) -> None`

Выводит список файлов.

#### `print_processes(processes) -> None`

Выводит список процессов.

#### `print_logs(logs) -> None`

Выводит журнал.

#### `main() -> None`

Запускает главный цикл оболочки.

Поддерживаются команды:

- `help`;
- `whoami`;
- `login`;
- `logout`;
- `create`;
- `ls`;
- `cat`;
- `delete`;
- `run`;
- `ps`;
- `kill`;
- `mem`;
- `echo`;
- `users`;
- `logs`;
- `clear`;
- `shutdown`;
- `exit`.

### Внутренние зависимости

Используются:

- `db.py`;
- `syscalls.py`;
- `os`.

`shell.py` не выполняет SQL напрямую.

### Обработка ошибок

Неправильное числовое значение обрабатывается через `ValueError`.

Остальные ошибки перехватываются через:

```python
except Exception as error
```

Ошибка команды не должна аварийно завершать оболочку.

### Побочные эффекты

Модуль:

- принимает ввод;
- выводит информацию;
- может очищать терминал;
- вызывает системные вызовы;
- выполняет `init_db()` при запуске.

# Автоматизированная проверка прав

Для автоматической проверки используется:

```text
tests/test_permissions.py
```

Запуск:

```bash
python -m tests.test_permissions
```

Ожидаемый результат:

```text
[PASS] TC-02: guest не может удалить файл admin
[PASS] admin может удалить файл user
[PASS] guest не может убить процесс
[PASS] admin может убить процесс
Все тесты пройдены.
```

Для защищённых системных вызовов в `syscalls_log` используются статусы:

```text
check
DENIED
OK
NOT_FOUND
```
